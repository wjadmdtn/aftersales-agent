# 售后客服 Agent

面向**售中 + 售后**（订单驱动的服务场景）的客服 Agent。核心不是"能聊天"，而是**不可逆操作怎么做得可控**，以及 **AI 处理不了的时候怎么平稳交给人工**。

当前进度：**转人工子系统已完成，50 个测试全部通过**。

---

## 设计取舍

| 决策 | 为什么 |
|---|---|
| **只做售中 + 售后** | 边界由业务入口自然划出：有订单才有售中售后，售前没有订单。售前"好"的标准无法客观定义，会毁掉可自动判分的评测集 |
| **单 Agent + 显式状态机** | 售后流程是线性的、顺序敏感的，正是多 Agent 的弱项。多 Agent 只在局部（退款决策复核）才有必要 |
| **优先级是纯规则函数** | 优先级决定真人的工作分配，必须可复现、可向主管解释，不能交给 LLM |
| **人工拒绝 → 不回流 AI** | 回流会造成 AI/人工来回踢皮球。拒绝即升级，由人工链路继续处理 |
| **摘要用规则版兜底** | LLM 不可用时上下文包仍要能生成，不能因为模型挂了就转不了人工 |

---

## 转人工：四类触发源

| 触发源 | 条件 | 策略 | 优先级 |
|---|---|---|---|
| ① 能力边界外 | 工具返回 NOT_FOUND/EMPTY、RAG 相似度低、LLM 判定无法处理 | **先给自助建议再转** | 中 |
| ② 风险触发 | 金额 ≥ 阈值、投诉关键词、情绪激烈 | **立即转，跳过自助建议** | **高** |
| ③ 用户主动要求 | 命中"转人工""找真人"等关键词 | **直接转，禁止挽留话术** | 高 |
| ④ 系统异常 | 工具连续失败 ≥ 3 次、schema 重放耗尽、LLM 连续超时 | 先道歉说明再转 | 中 |

优先级判定顺序：`风险触发 > 情绪激烈 > 金额超阈值 > 用户主动要求 > 其他`。

**注意**：风险触发一定跳过自助建议——在风险场景下多解释一轮只会激化用户。

## 状态机

```
INTENT ─┬─→ COLLECTING → VALIDATING → DECIDING → EXECUTING → DONE
        ├─→ RISK_BLOCK ─────────────────────────┐
        └─→ HANDOFF_REQUESTED ──────────────────┤
                                                ▼
                                             QUEUED  ← 只在人工侧事件驱动下流转
                                                │
                                                ▼
                                          HUMAN_SERVING  ← AI 完全静默
                                                │
                                     ┌──────────┴──────────┐
                                  RESOLVED               （人工拒绝则升级，不回 AI）
```

### 两条硬约束

1. **`HUMAN_SERVING` 是静默区**：人工接管后 AI 不得发送任何消息，违反即视为事故
2. **`QUEUED → HUMAN_SERVING` 只能由人工侧事件触发**：Agent 不能自己"模拟接入"

这两条都有单测覆盖（`tests/test_state.py`）。

---

## 上下文包（Context Pack）

人工客服一次要看多个会话，不读摘要就得从头翻聊天记录。转接时打包：

| 字段 | 说明 |
|---|---|
| `summary` | ≤ 120 字，AI 生成（规则版兜底） |
| `attempted_actions` | 已尝试的工具调用及结果，结构化而非自然语言 |
| `primary_intent` / `intent_confidence` | 用户诉求与置信度 |
| `sentiment` | 情绪，影响优先级 |
| `priority` / `priority_reason` | 优先级**必须写明依据** |
| `trigger_type` / `trigger_detail` | 四类触发源之一 |
| `suggested_next_step` | AI 建议，人工可改；风险触发时为空 |

## 运行

```bash
# 安装
uv venv && uv pip install -e ".[dev]"

# 配置（所有规则均可通过环境变量覆盖）
cp .env.example .env

# 测试
python -m pytest -q
```

Windows 下需带 `PYTHONIOENCODING=utf-8` 运行 pytest，否则中文关键词会因控制台 GBK 编码匹配失败。

## 目录

```
app/
├── config.py              # 全部规则可配置，含校验
├── models.py              # 领域模型（状态、触发源、上下文包）
└── handoff/
    ├── triggers.py        # 四类触发源 + 固定优先级顺序
    ├── priority.py        # 优先级计算（纯函数）
    ├── context_pack.py    # 上下文打包 + 摘要生成
    ├── state.py           # 状态机 + AI 静默约束
    └── queue.py           # Redis 队列（幂等 + 优先级排序）
tests/                     # 50 个用例，覆盖所有边界
```

---

## 已知边界

- 尚不包含：工具层与 mock 业务服务、Agent 主循环、评测集（下一步）
- `attempted_actions` 为空时视为合法（本轮未调工具），不计入完整性问题
- 情绪判定目前只依赖关键词规则；LLM 情绪分类作为后续增强
